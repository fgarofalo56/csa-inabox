# Installed as a SECOND pip pass, AFTER requirements.txt, in both the Dockerfile
# and the `transform-runner-imports` job of .github/workflows/python-deps-resolve.yml
# so the image and CI can never disagree about what actually ships.

# WHY A SECOND PASS INSTEAD OF A LINE IN requirements.txt
# -------------------------------------------------------
# These pins deliberately VIOLATE a transitive dependency's declared range. Put
# them in requirements.txt and pip's resolver backtracks over dbt-core /
# dbt-common looking for a combination that satisfies everything, finds none,
# and dies with ResolutionImpossible — i.e. it would re-break the build the way
# the protobuf conflict did before #2627. A second `pip install` overrides the
# already-resolved tree, prints a loud "dependency conflicts" advisory, and
# exits 0. The Dockerfile ASSERTS the resulting version so the override cannot
# silently no-op.
#
# ── deepdiff — CVE-2025-58367 (CRITICAL) ───────────────────────────────────
# Found by the SC1 Trivy gate on the FIRST image loom-transform-runner ever
# built (run 30402200538, image tag f3b4d6875d…): deepdiff 7.0.1, fixed 8.6.1.
# It was the ONLY CRITICAL in the image — the debian 13.6 OS layer and the one
# node-pkg target (jupyterlab-manager's package.json, via ipywidgets) both
# scanned 0.
#
# INTRODUCED BY: dbt-common 1.27.1 (`deepdiff<8.0,>=7.0`) — nothing in this
# app's own source imports deepdiff. dbt-common is not directly pinned here; it
# is fenced at 1.27.1 by dbt-core 1.8.9's `protobuf<6.0` (dbt-common 1.28.0+
# moved to `protobuf<7.0,>=6.0`), which is the same protobuf fence documented at
# length in requirements.txt.
#
# WHY UPGRADE-IN-PLACE IS THE CORRECT FIX, NOT A WAIVER:
#   * dbt-common RELAXED this very pin to `deepdiff<9.0,>=7.0` at 1.29.0 and has
#     kept it there through 1.38.0 — upstream considers deepdiff 8.x compatible
#     with its own usage. We cannot TAKE dbt-common 1.29.0+ only because it
#     drags protobuf 6, not because of deepdiff.

#     `from deepdiff import DeepDiff` inside `dbt_common/record.py::Diff.__init__`

#     replacing 7.x's ordered-set. deepdiff 9.x additionally requires cachebox
