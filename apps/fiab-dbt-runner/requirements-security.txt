# WHY A SECOND PASS INSTEAD OF A LINE IN requirements.txt

# These pins deliberately VIOLATE a transitive dependency's declared range. Put
# them in requirements.txt and pip's resolver backtracks over dbt-core /
# dbt-common looking for a combination that satisfies everything, finds none,
# and dies with ResolutionImpossible. That is not theoretical here: the
# 2026-07-31 build log of this very image (run 30600236939, job 91063974608)
# shows pip trying `deepdiff<9.0,>=7.0` -> 8.6.2 first, then BACKTRACKING to
# `deepdiff<8.0,>=7.0` -> 7.0.1 once it re-resolved dbt-common under
# dbt-core 1.8.9's protobuf fence. A second `pip install` overrides the
# already-resolved tree, prints a loud "dependency conflicts" advisory, and
# exits 0. scripts/assert_security_pins.py then ASSERTS the resulting version
# so the override cannot silently no-op.
#
