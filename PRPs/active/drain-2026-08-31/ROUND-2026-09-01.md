## 2a. A correction, recorded because the wrong premise is contagious

**#4275 was filed on a mechanism I got wrong**, and the error is worth keeping
rather than quietly overwriting, because the same mistake is easy to repeat.

I opened it on a `--check` output reporting *"20 differing field(s)"* of the form
`console:member:2791 -> console:member:2842`, and concluded the artifact keyed
node identity to a **positional ordinal**, making any scanned-file addition
re-stale every open PR.

Measured on PR #4273's regeneration (job `99971781647`): the artifact's **git
diff is a clean insertion — 49 insertions, 7 deletions, no cascade.** The 20-field
cascade exists **only in the comparator's output**, because
`_artifact-drift.mjs` walks arrays **by index**. One node inserted mid-array
makes every later position report as differing.

So the ids were never the problem, and "one merge re-stales every open PR" is
false at the file level. The three PRs that triggered this each had **genuine,
PR-local** drift from their own added `.mjs` under `scripts/**`.

**The generalisable lesson:** a diff tool's output is a claim about *how it
walked*, not only about the data. `deploy-integrity.md` R7 applies to
diagnostics as much as to errors — *"20 differing fields (there may be more)"*
asserted widespread corruption when the truth was one added node, and it cost
several steps of investigation down the wrong path.

**Secondary lesson on evidence:** I treated a *count* (20 fields) as a measure
of *extent*. It was a measure of the walk. Prefer evidence that names the
subject — "which node?" — over evidence that counts positions.
