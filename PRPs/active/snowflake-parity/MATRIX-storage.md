# MATRIX — Storage & table types (Snowflake → CSA Loom)

**Domain key:** `storage`
**Posture (binding, 2026-08-24):** MIGRATION-FIRST. Loom is the destination. The MCP
connector exists to read a customer's existing Snowflake account and extract their data and
definitions. Interop is the means, not the end state.
**SQL dialect (binding):** offline transpiler NOW (Snowflake SQL / dbt / DDL / stored procs →
Loom engines); Snowflake-wire-compatible endpoint is a LATER wave.
**Parity depth (binding):** OUTCOME parity with differences NAMED. Mechanism parity
(micro-partition internals, Fail-safe, Snowgrid) is explicitly rejected.

## Legend

**Status** — `built` = exercisable end-to-end at Snowflake-outcome parity today ·
`partial` = a real substrate exists, the capability does not · `missing` = no implementation ·
`cannot-match` = a named, permanent gap (no design invented for it).

**Boundaries** — ✅ same design works · ✅ˢ works only via the named substitute (substitute is
named in the Target-architecture cell) · ⚠️ works degraded (degradation named) · ❌ does not work.

**Databricks rule (blocking):** Azure Government has **no Databricks SQL and no Unity Catalog**.
Any Gov ✅ resting on a Databricks call is wrong by rule. Every row below that touches Databricks
routes Gov to Synapse Spark (Livy), Trino, DuckDB, or Loom Unity OSS instead.

## Cross-row dependencies (build order matters)

1. **Micro-partition parser** (`readCommitFileEntries`) is the keystone — clustering depth, pruning prediction, per-table metrics, retention read-back, clone-group detection, staleness triggers, and the archived-active-set check **all** derive from it.
2. **Metadata cache** must land before anything that reads it per page load, or every open re-walks ADLS.
3. **Clone-group registry** must land before per-table byte accounting (otherwise shallow-clone bytes double-count) **and** before the lifecycle/VACUUM guards (otherwise the clone footgun ships with a reassuring UI).
4. **Autotune job** is the shared actuator for automatic clustering, Optima inference/indexing/planning, transient GC, session-object GC, backup sets, daily cost snapshots, and Iceberg maintenance. It is also what turns `timeTravelDays`, `deltaDefaults.autoOptimize` and `liquidClustering.columns` from dead Cosmos values into real behaviour.
5. **Trino read-only posture** blocks native-Iceberg maintenance; it needs a scoped, audited maintenance rule, not a blanket flip.
6. **WORM** conflicts with VACUUM/OPTIMIZE, PITR, last-access tracking, transient tier, and teardown — build its refusals alongside it, not after.
