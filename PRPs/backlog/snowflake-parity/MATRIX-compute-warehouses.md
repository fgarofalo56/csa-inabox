# Parity matrix — Compute & warehouses

**Parent:** [`PRP.md`](./PRP.md) · Measured 2026-08-24 · **50 rows**

Every Snowflake compute capability, what Loom has today, the target Azure-native/OSS
architecture, the per-boundary verdict, effort, and — the column that matters most — the
**semantic delta** a migrating user hits on day one.

## How to read this

- **Loom today** — `Built` (real backend, works) · `Partial` (mechanism exists, missing the
  per-object dimension / Gov path / UI) · `Missing` · `Cannot match` (see PRP §6).
- **Gov** — Commercial ≠ Gov. Per `cloud-parity.md`, **any row whose Commercial mechanism is
  a Databricks SQL REST call is Synapse-only in Gov**, because `usgovaz` and `usgovva` do
  not support Databricks SQL or Unity Catalog (Microsoft, verified 2026-08-24).
  ✅ = same capability both · ⚠️ = degraded/different path · ❌ = not achievable.
- **Effort** — S (days) · M (1–2 weeks) · L (2–4 weeks) · XL (4+ weeks).
- **W** — the work item in `PRP.md` §8 that owns it.

Where a research design carried a factual error about Snowflake's own semantics, the
**corrected** value is used here and the correction is numbered per `PRP.md` §7.
