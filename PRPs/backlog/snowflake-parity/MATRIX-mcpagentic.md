## Binding posture (operator decisions, 2026-08-24)

1. **MIGRATION-FIRST.** Loom is the destination. The Snowflake MCP connector exists mainly to
   *read a customer's existing account and get their data and definitions out*. Interop is the
   means, not the end state. The research lane's coexistence recommendation is **OVERRULED**.
   **Sequencing consequence for this domain:** the rows that make Loom's own agentic surface
   real and governable (**M2 deploy, M25 identity, M26 attribution, M6 per-tool RBAC**) rank
   ABOVE the rows that deepen third-party interop (**M11 Glean/Salesforce, M12 Google
   Workspace, M13 custom connectors**). The research implicitly ordered these the other way;
   that ordering is superseded here. Note also that **no row in this domain covers the
   outbound Snowflake-reading connector itself** — the research scoped only Loom's own MCP
   surface. That connector rides the existing custom-connector path (M13) and is owned by the
   migration/transpiler domain, not this one. Flagged so it is not assumed covered.
2. **TRANSPILER NOW, WIRE-COMPATIBLE LATER.** Affects **M3, M4, M17**: an MCP tool that emits
   or accepts SQL must accept **Snowflake dialect via the offline transpiler** and must not
   wait on, or assume, a Snowflake-wire-compatible endpoint. That endpoint is a later wave.
3. **OUTCOME PARITY, DIFFERENCES DOCUMENTED.** The *Semantic delta* column is the
   implementation of this decision. Mechanism parity is explicitly not the goal; a named
   difference in a doc beats a silent difference in production.

## How to read this

- **Loom today** — `Built` (real backend, deployed, works) · `Partial` (mechanism exists;
  missing the deployment, the descriptor, the per-object dimension, or the UI) · `Missing` ·
  `Cannot match` (no faithful equivalent exists — say so, don't invent one).
- **Boundaries** — ✅ same capability, same mechanism · ⚠️ same capability via a **named
  substitute** (never a blank — `cloud-parity.md` makes a blank a defect) · ❌ not achievable.
- **The single boundary fact that governs most of this domain:** `apps/fiab-mcp-bridge/README.md:20`
  and `:75` state **"Container Apps not at IL4+"** — Container Apps for Commercial/GCC, an
  **AKS workload for GCC-High/IL5/DoD**, selected by the existing `containerPlatform` param
  (`platform/fiab/bicep/main.bicep:56`). Every ACA-hosted row below is therefore ⚠️-with-AKS in
  the top three boundaries, never ❌.
- **Databricks caution.** Azure Government supports **neither Databricks SQL nor Unity
  Catalog**. Any Gov verdict resting on a Databricks call is wrong by rule. Where a design's
  Commercial arm is Databricks, the Gov arm is named separately (Synapse / ADX / Azure SQL /
  Loom Unity + Trino).
- **Effort** — S (days) · M (1–2 wk) · L (2–4 wk) · XL (4+ wk).
