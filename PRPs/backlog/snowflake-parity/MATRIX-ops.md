Every Snowflake operations / cost / observability capability, what Loom has today, the

that matters most — the **semantic delta a migrating user hits on day one**.

## Binding posture (operator, 2026-08-24)

1. **Migration-first.** Loom is the destination. The MCP connector reads a customer's
   existing Snowflake account to get data and definitions *out*. Coexistence was
   recommended by a research lane and is **overruled** — interop is the means, not the end
   state. Rows below sequence extraction ahead of interop.
2. **Transpiler now, wire-compatible later.** Offline conversion of Snowflake SQL / dbt /
   DDL / stored procedures ships first. A Snowflake-wire endpoint is a later wave. No row
   here assumes an existing Snowflake driver connects to Loom.
3. **Outcome parity, differences documented.** Match what a user can *exercise and
   observe*, using the best Azure/OSS mechanism underneath. Mechanism parity (micro-partition
   pruning, Fail-safe, Snowgrid internals) is **rejected**. Where semantics genuinely
   differ, the delta column names it so the user meets it in a doc, not in production.

## How to read this

- **Loom today** — `Built` (real backend, works end-to-end) · `Partial` (mechanism exists;
  missing the per-object dimension, the Gov path, or the surface) · `Missing` ·
  `Cannot match` (a hard mechanism difference; see §Named gaps).
- **Boundaries** — ✅ same capability · ⚠️ degraded / different path, **substitute named**
  · ❌ not achievable. Per `cloud-parity.md` a blank is not permitted.
  - **GCC rides Azure Commercial infrastructure**, so Databricks SQL is available there.
  - **GCC-High, IL5 and DoD ride Azure Government**, which **does not support Databricks
    SQL or Unity Catalog**. Any design whose only mechanism is a Databricks REST call is
    ❌ in those three by rule, and the row names the Synapse / ADX / Trino substitute.
  - **DoD (US DoD Central/East)** carries a materially narrower authorized service list
    than US Gov Virginia/Arizona/Texas. Where ADX or ACA is thin, the named substitute is
    Log Analytics custom tables (DCR-ingested, same KQL) or Delta-on-ADLS via Trino.
- **Effort** — S (days) · M (1–2 weeks) · L (2–4 weeks) · XL (4+ weeks).
- **Evidence** — a real `file:symbol` or line, or the search that returned nothing. Every
  "missing" claim below was re-measured against the current tree, not inherited.

## Named gaps — where the capability genuinely cannot be matched

Two rows are `Cannot match`. Both are named rather than designed around, because a plausible
fiction here would be worse than the gap.

1. **Adaptive Warehouses (row 6).** Snowflake resizes **between queries from a shared account
   pool with no disconnect, bills per query, and does not bill an adaptive warehouse for
   existing**. Loom bills wall-clock, and the only Gov-viable resize actuator — a Synapse DWU
   change via `scalePool()` — transits `Scaling` and **disconnects running queries**, with
   `waitForOnline(maxMs=180_000)` as the honest recovery bound. The scoped per-warehouse loop
   is a genuine improvement and should ship; it is **not** the same capability, and the surface
   must not imply it is.

2. **Replication groups (row 29).** The capability *is* the atomicity: one
   transactionally-consistent point in time across databases, warehouses, users and roles,
   with one failover verb. That cannot be layered over Azure SQL failover groups, Cosmos
   multi-region, ADLS object replication, Event Hubs geo-DR and ADX followers, which fail over
   **independently to different points in time**. Loom ships a *coordinated group with
   per-plane consistency* and a single headline number defined as **the oldest plane's
   consistency point** — the only honest way to express one number.

Two further capabilities are matched only in **degraded** form and are called out here so they
are not mistaken for parity:

- **Reader accounts (row 9)** — an identity with scoped RBAC, not a separate account; cross-boundary
  B2B is policy-blocked in GCC-High/IL5/DoD, and **Commercial↔Gov sharing is not achievable at all**.
- **Organization Hub account creation (row 22)** — subscription-alias creation is agreement-dependent
  and restricted in Azure Government; **cross-boundary account creation is impossible by policy**,
  not merely unimplemented.
